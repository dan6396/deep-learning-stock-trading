# 가격·뉴스 결합 효율 탐색 실험

이 실험은 기존 악재 필터와 별개입니다. 가격 후보와 독립적인 뉴스 후보를 합쳐,
뉴스로 가격 20위 밖의 종목도 선택할 수 있게 합니다. 기존 Huber 가중치와
`portfolio_replay.py`를 유지합니다. 실서비스의 기본 매수 규칙을 교체하지 않습니다.

## 결과 전에 고정하는 비교 조건

- 기간: 기존 평가 파일의 첫 10거래일, 2026-06-01~06-15. 이미 관찰한 구간입니다.
- Universe: 해당 날짜별 기존 KOSPI200 예측 파일의 유효 종목 전부. 날짜별 200개,
  구간 전체는 구성 차이로 204개 코드입니다. 당시 지수 구성 복원을 새로 수행하지 않습니다.
- 후보: 가격 상위20 / 가격 상위20과 독립 뉴스 상위10의 합집합.
- 대표 기사: 후보 종목별 1건 / 2건.
- 뉴스 비중: 25% / 50% / 75%.
- 총 12개 조합과 가격 단독 기준선. 모든 조합을 공개하며 관측 1위를 최종 모델로 자동 채택하지 않습니다.
- 매수일08:30 이전, 최근3일 뉴스. 불확실한 시각은 다음 달력 날짜부터 허용합니다.
- 투자금1,000만원, 첫5종목 동일 현금 배분, 유지 종목 수량 유지, 이탈 종목만 시가 교체,
  마지막 종가 청산, 편도 비용0.125%, 소수점 주식. 매일 비중 재조정은 아닙니다.

## 비용을 줄이는 경로

전체 종목에서 제목·기업명·시각을 수집하는 데 유료 LLM을 사용하지 않습니다.
정규화한 기업명이 제목에 나타나며 기업 사건 키워드가 있는 기사를 우선합니다.
실적·계약·자본·법률·제품 사건의 종류 수와 최신성으로 뉴스 후보를 선정합니다.
이는 중요도를 추정하는 단순 규칙이며 호재 점수나 기대수익률이 아닙니다.
동점은 종목 코드로 결정해 가격 순위가 뉴스 후보 선별에 개입하지 않게 합니다.

현재 시점에 사용 가능한 기사끼리만 제목 유사도로 중복 제거합니다. 숫자 정보가 다르면
별개 기사로 둡니다. 완전한 사건 군집화는 아니며, 누락과 기업명 오연결 가능성이 남습니다.
최대30종목×대표2건이므로 하루 최대60개 본문 슬롯이고, 여러 날·조합에서 동일 본문은
재사용합니다. 본문 실패 후 다른 기사를 추가로 골라 성공률을 사후 개선하지 않습니다.

기존 OpenAI 분석은 동일 본문·모델 스냅샷·프롬프트이며 과거 호출 배치의 정보시점이
이번 사용 시점보다 늦지 않을 때만 재사용합니다. 기존 거절 결과도 조건이 같으면 재사용하여
원하는 답이 나올 때까지 반복 요청하지 않습니다. Gemini 결과는 섞지 않습니다.

추가 API 비용 상한은 실험 전체 $1입니다. 요청 전 보수적 최대 비용을 장부에 예약하고,
응답 사용량으로 추정액을 정산합니다. 실패·불명확 요청 예약액은 유지하고 자동 재시도하지
않습니다. 공식 단가 기준 추정액이며 청구서 금액은 아닙니다. 키는 `.env.news_fusion`에서만
읽고 출력·산출물·Git에 넣지 않습니다. 이전 분석 비용 및 수집 운영비는 별도입니다.

## 결합 점수와 지표

가격 점수는 당일 전체 Universe 내 순위를 [-1,1]로 변환합니다.
뉴스 점수는 긍정1/중립0/부정-1에 직접 관련1/간접 관련0.5를 곱하고,
24시간 지수 감쇠로 평균합니다. 결합은 `(1-w)*가격점수 + w*뉴스점수`입니다.
본문 미확보·시간 제외·분류 거절·관련성 부족·미요청을 별도 기록합니다.
사용 가능한 뉴스가 없을 때 기여도를0으로 하는 것은 운영상 대체 규칙이며 중립 판정이 아닙니다.
두 점수의 범위는 같아도 정보량이나 예측력이 같은 것은 아닙니다.

최종 자산, 수익률, MDD, Sharpe, 거래비용, 양방향 거래대금/기초자산 회전율 합,
Top5의 평균 일중 수익, 공통 Universe의 정책 Rank IC, 가격20 밖 선택 수,
뉴스 근거 확보율, 고유 기사 수와 본문 길이를 저장합니다.
정책 Rank IC는 후보 우선·후보 내 결합 점수·나머지 가격 순으로 정렬한 순위의 IC입니다.
원래 회귀 예측값의 IC와 구분해야 합니다. 합성 순위 점수의 부호를 상승/하락 예측으로
간주하지 않으므로 방향 정확도는 만들지 않습니다.

본문 수는 시간 조건을 통과한 고유 종목·본문 쌍입니다. 한 기사에 여러 기업이 등장하면
대상 기업마다 별도로 분석하므로 전체 웹의 고유 기사 수와는 다릅니다.
본문 수·글자 수는 조합별 비용 비교의 대용 지표입니다. 모든 조합이 분석을 공유하기 때문에
실제 총 비용을 조합별 실제 청구액으로 해석하지 않습니다. API 비용은 달러로 별도 보고하며
원화 투자 성과에 임의 환율로 섞지 않습니다. 수집·본문 처리시간은 캐시 포함 실행시간입니다.

## 재실행

저장소 루트에서 실행합니다. 각 단계 성공을 확인한 후 다음 단계로 진행합니다.

```bash
python run_news_efficiency.py prepare
python run_news_efficiency.py collect
python run_news_efficiency.py plan
python run_news_efficiency.py bodies
python run_news_efficiency.py analyze
python run_news_efficiency.py replay
python run_news_efficiency.py report
python -m unittest discover -s tests -p "test_news*.py" -q
```

기본 출력은 `outputs/news_efficiency_20260601_0615/`입니다. `--out`, `--source`,
`--predictions`, `--bars`, `--env-file`로 경로를 지정합니다. 원래 실험 자료는 덮어쓰지 않습니다.
`protocol.json`은 비교 조건과 소스 해시, `metrics.json/csv`는 모든 성과,
각 전략의 `*_decisions.csv`는 후보·가격 및 뉴스 기여도·기사 근거를 담습니다.
`report.html`은 이미지가 포함된 독립 문서입니다. PNG 두 개도 별도로 생성합니다.
