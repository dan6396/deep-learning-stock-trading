# 최종 모델 웹 화면

## 운영 서버와 관리자 인증

FE/vercel.json과 api/*는 지원하지 않는 배포 경로다. 단일 Node 인스턴스(npm run start)만 지원한다. 파일 기반 배포는 시작 시 토큰 검사를 보장하지 않고, 프로세스 내 실행 잠금·제한기를 공유하지 않으며, 브리핑 API 진입점도 없습니다. 기존 파일은 남겨 두지만 배포에 사용하지 않습니다.

같은 종류의 동시 분석 요청은 진행 중인 실행을 공유합니다. 요청 종류가 다르면 409와 현재 runId·kind·재시도 안내를 반환하므로 공식 예약 작업은 완료 후 재시도해야 합니다. [API 계약의 외부 스케줄러 예시](docs/api-contract.md#외부-공식-실행-예약)를 따르세요. 브리핑 응답의 kind는 결과의 실행 메타로 판단하며 수시 결과에는 ‘수시 분석 결과 · 공식 기록 아님’을 표시합니다. 구분할 수 없는 이전 결과는 unknown이며 표시를 생략합니다.

Node 24에서 `npm ci`, `npm run build`, `npm run start` 순으로 실행합니다. `start`는 런타임 의존성 `tsx`로 `server/prodServer.ts`를 실행하므로 Vite 개발 서버 없이 API와 `dist`를 함께 제공합니다. 기존 서버 모듈의 확장자 없는 TS import를 유지하고 별도 서버 빌드 산출물 없이 실행하기 위해 tsx를 사용합니다. 배포에는 `server/`, 서버가 참조하는 `src/` 타입·공용 모듈과 기존 모델/출력 경로도 필요합니다. `vite preview`는 정적 점검 전용입니다.

환경 변수는 프로세스 환경으로 주입합니다. 운영 서버는 Vite의 dotenv 로딩을 사용하지 않습니다. 기본 `PORT=3000`, `HOST=0.0.0.0`입니다. 정적 `/about`은 프리렌더 파일을 우선하고 다른 페이지 경로는 SPA로 연결합니다. 보안 헤더를 기본 제공하며 성과 수집과 refresh-ahead는 시작 때 기동하고 SIGINT/SIGTERM·서버 종료 때 타이머를 정리합니다.

| 변수 | 용도 |
| --- | --- |
| `ADMIN_API_TOKEN` | 관리자 POST Bearer 토큰. 브라우저용 `VITE_` 변수에 넣지 않습니다. |
| `CRON_SECRET` | 예약 작업 Bearer 토큰. 관리자 토큰과 서로 다른 값을 사용합니다. |
| `SNAPSHOT_REFRESH_KEY` | refresh POST 키. trim 후 빈 값은 미설정이며, 설정된 값이 32자 미만이면 시작을 거부합니다. query `key`보다 `x-refresh-key` 헤더 전달을 권장합니다. |
| `TRUST_PROXY` | 기본 비활성. 신뢰하는 프록시 홉 수 N(양의 정수)입니다. X-Forwarded-For의 오른쪽 N번째 주소를 사용합니다. `1`은 마지막 주소입니다. 원본 서버 직접 접근을 차단하고 모든 신뢰 홉에서 실제 peer를 추가하거나 헤더를 덮어써야 합니다. |
| `DEV_ALLOWED_HOSTS` | Vite에서 허용할 호스트 이름의 쉼표 목록. 빈 값이면 Vite 기본 검사입니다. 설정됐는데 관리자·cron 토큰이 모두 비어 있으면 개발 서버 시작을 거부합니다. |

`POST /api/candidates/run`은 관리자가 호출하면 항상 `adhoc`이며 `kind=official` 요청은 403입니다. 장 마감 후 외부 스케줄러만 CRON_SECRET으로 `POST /api/candidates/run?kind=official`을 호출하도록 구성합니다. 서버는 공식 분석 자동 일정을 새로 만들지 않습니다. narrative 생성·성과 수집 POST는 관리자 또는 cron 토큰이 필요합니다. 인증 없음/불일치는 401입니다. 쓰기는 먼저 토큰을 검증하고 관리자·cron은 각각 별도 분당 30회 버킷을 사용합니다. 유효한 refresh 키와 로컬 개발 예외도 별도 분당 30회 버킷입니다. 미인증 요청은 IP별 분당 10회로 제한하므로 익명 요청이 cron을 막지 않습니다. 초과하면 429와 Retry-After(초)를 반환하며 IP 맵 포화 시 가장 오래된 항목을 제거합니다. 제한과 분석 실행 잠금은 단일 Node 프로세스 범위이므로 한 인스턴스로 운영합니다.

운영 서버 시작 시 ADMIN_API_TOKEN·CRON_SECRET의 앞뒤 공백을 제거해 검사합니다. 빈 토큰은 경고하고 해당 인증을 거부합니다. 설정한 값이 32자 미만이거나 두 값이 같으면 시작을 거부하며 토큰 값은 로그에 남기지 않습니다. refresh POST는 query `key` 또는 `x-refresh-key` 헤더의 `SNAPSHOT_REFRESH_KEY`를 검사하고, 운영에서는 키 미설정도 401입니다. refresh GET은 기존 cron Bearer 인증입니다. 동시 snapshot 갱신은 한 번의 전체 빌드·저장을 공유합니다.

개발 분석·요약·성과 POST는 **관리자·cron 토큰이 모두 비어 있을 때만**, refresh POST는 snapshot 키가 비어 있을 때만 로컬 예외를 허용합니다. 공통 조건은 실제 loopback peer, Host 호스트명 localhost/127.0.0.1/[::1], 전달 헤더(x-forwarded-*·forwarded·cf-connecting-ip·cf-ray) 없음입니다. Origin이 있으면 요청의 scheme·Host와 같은 origin이어야 합니다. Origin이 없으면 Sec-Fetch-Site가 same-origin/none이거나 없어야 합니다(curl). 터널 공개 전에는 반드시 토큰을 설정하세요.

운영 CSP는 self 출처와 빌드된 index.html에서 시작 시 계산한 테마 스크립트 SHA-256 해시만 script-src에 허용합니다. style-src의 unsafe-inline은 React style 속성·초기 배경 때문에 유지하고 이미지·폰트의 data: URI를 허용합니다. connect-src는 self이므로 운영 API도 같은 origin으로 제공합니다. `/assets/*`는 1년 immutable, HTML은 no-cache·mtime/size 기반 ETag·304를 지원하며 텍스트 자산은 Accept-Encoding에 따라 gzip과 Vary를 제공합니다. `/api`는 SPA 대신 404 JSON입니다. 비동기 API 오류는 500 JSON으로 처리하고 서버 포트 충돌은 EADDRINUSE 안내를 남깁니다.

`connect-src 'self'` 때문에 운영 빌드의 `VITE_API_BASE_URL`에 다른 오리진을 지정할 수 없습니다. 같은 오리진의 API 경로를 사용하세요. TCP 터널(`ssh -R`)은 HTTP 전달 헤더 없이 loopback·로컬 Host 조건을 유지해 개발 로컬 예외를 통과할 수 있으므로 터널 공개 전 토큰을 반드시 설정해야 합니다. refresh 키는 URL 기록에 남는 query보다 `x-refresh-key` 헤더로 전달하세요.

정적 전송은 pipeline이 원본·gzip·응답 스트림을 함께 관리합니다. 클라이언트 중단은 조용히 정리하고 다른 오류는 응답 가능한 경우 500과 `Cache-Control: no-store`를 반환합니다. unhandledRejection 로그에는 오류 name·code만 남기고 메시지는 제외합니다. 제한기 맵 전체의 만료 정리는 요청 시 최소 1초 간격으로 수행하며, 요청한 IP의 만료는 즉시 반영합니다.

화면 URL에 `?admin`을 붙여 관리자 대화상자를 열고 password 입력란에 토큰을 저장합니다. 현재 탭의 sessionStorage에만 보관하고 POST에만 Authorization을 첨부합니다. 같은 대화상자의 ‘해제’로 지웁니다. 토큰이 없어도 개발 서버에서 ADMIN_API_TOKEN과 CRON_SECRET이 모두 비어 있고, localhost·127.0.0.1·[::1]로 접속해 `/api/backend/status.localWriteAllowed`가 true로 확인되면 실행/요약 생성 버튼을 표시합니다. 그 외에는 토큰이 없으면 숨깁니다. 로컬 모드에서 저장된 토큰이 없으면 ‘해제’는 비활성화됩니다. `VITE_DEMO_HIDE_RUN=1`도 계속 지원합니다. 401이면 토큰 재입력, 403이면 수시 실행, 429이면 안내한 시간 후 재시도합니다. 공개 서버는 HTTPS로 제공합니다.

터널 시연은 PowerShell에서 `$env:DEV_ALLOWED_HOSTS='example.trycloudflare.com,example.ngrok-free.app'`처럼 실제 호스트 이름을 설정하고 관리자/cron 토큰을 주입한 뒤 Vite를 시작합니다. URL 스킴·경로는 넣지 않습니다. 호스트가 바뀌면 목록을 수정하고 재시작합니다. 모든 호스트 허용 설정은 사용하지 않습니다.

루트 [실행 안내](../README.md)와 [API 계약](docs/api-contract.md)을 기준으로 실행합니다.

```powershell
npm ci
npm run dev -- --host 127.0.0.1
```

현재 경로는 `/` 브리핑, `/rank` 전체 순위, `/stock/:code` 종목 리포트, `/watchlist` 관심 목록, `/history` 실행·성과 기록, `/about` 소개입니다. `/next`는 같은 현재 화면으로 연결되는 별칭이며 별도 구현이 아닙니다. 이전 `/legacy` 화면은 제거했습니다.

브리핑 실행은 최종 20일·120일 모델 순위와 TOP5 관련 RSS 기사를 표시합니다. 순위 점수는 수익률이나 상승확률이 아닙니다. 저장 성과는 실제 시가·종가가 모두 확보된 선정 종목으로 계산합니다.

기본 manifest는 `models/final_rank_ensemble/manifest.json`입니다. `PIPELINE_MODEL_MANIFEST`로 이를 덮어쓸 때도 최종 모델 형식만 허용합니다. `PIPELINE_ANALYSIS_MODE`는 `model_only`만 지원합니다. 실행 결과는 루트 `outputs/`에 생성합니다. 실제 API/Python 작업에는 개발 서버 또는 API 서버가 필요하고 정적 preview만으로는 실행되지 않습니다.

API: `GET /api/briefing`은 모델 TOP5·시장 지표 7종(코스피200 야간선물 포함)·기사 출처·근거·주의와 설명을 반환합니다. GET은 LLM을 호출하지 않습니다. `POST /api/briefing/narrative`로 설명을 생성하며 모델 순위는 변경하지 않습니다. 키 없음·오류 시 템플릿으로 동작하고, 갱신 실패 전에 성공한 설명이 있으면 그 설명을 유지합니다. 미국 지표는 정규장 마감/장중 상태와 관측일을 표시하며 모델 기준일 다음 한국 거래일의 시가→종가 대상과 구분합니다.

개요·시장 설명·종목 설명은 필드별로 검증합니다. 실패 필드만 템플릿으로 대체하고 `narrative.fieldSources.overview/marketNote`, `narrative.stocks[].source`로 표시합니다. 일부가 LLM이면 `status="llm"`과 `fallbackReason="partial_template"`, 모두 실패하면 `status="template"`입니다. 숫자는 단위·절댓값과 상승/하락·순매수/순매도 방향을 함께 확인하며 기사 제목의 계약금액은 수치 근거로 쓰지 않습니다. 공개한 수급은 원 단위 한국어 금액(예: `20억 8,200만 원`)으로 통일합니다.

`macro.reference`는 저장된 1년 나스닥·코스피 참고 통계이며 LLM 입력에서 제외합니다. `composition`은 동일 비중(각 20%) 참고 구성·KIS 지수업종 중분류·검증된 공식 `model_only` 성과(최대 10일)와 공통 주의입니다. 업종을 확인하지 못하면 null입니다. 수급 공개는 서버 `BRIEFING_SHOW_SUPPLY`로 제어하며 기본은 false입니다. 이때 순위·종목·브리핑 API와 LLM 입력·템플릿·해시에서 수급 값·일수·관련 근거/주의를 제외합니다. 검증된 환경에서만 true 또는 1로 활성화하고, 활성화한 경우 조건 통과 대신 측정한 금액·일수를 설명합니다. 키·시간·수치·단위 검증과 정확한 응답 필드는 API 계약을 따릅니다.

업종은 실전 KIS 구성에서 조회합니다. 모의 구성이나 실전 도메인에 모의 앱키를 사용해 `EGW02004`가 발생하는 경우 `composition.sectors/sectorSource=null`을 유지합니다. 다른 KIS 시세 API의 성공만으로 업종 API 지원을 보장하지 않습니다. 서버 안전 로그의 오류 코드·메시지로 원인을 확인하고 실전/모의 키와 도메인을 함께 맞춰야 합니다.

KIS 공통 스로틀 `KIS_MAX_RPS`는 실전/모의 모두 기본 1건/초이며 한꺼번에 보낼 수 있는 토큰은 1개입니다. 공식 계좌 한도는 실전 18건/초·모의 1건/초지만 이번 환경은 5 RPS에서 한도 초과가 발생했고 1 RPS 단일 서버 실측 52회에서는 `EGW00201`이 0건이었습니다. 현재 키의 실효 안정 한도는 1건/초로 판단합니다. 공개 서비스에서는 기본값을 사용하고 실전 키의 한도를 확인한 운영자만 환경변수로 올리세요. `EGW00201`은 750ms 후 한 번만 재시도하며 설정은 공식 상한까지 제한합니다. 다른 Node 서버·Python 작업의 호출은 같은 계좌 한도를 사용하지만 이 프로세스의 스로틀에 합산되지 않습니다. 근거와 상세 동작은 [API 계약](docs/api-contract.md)을 따릅니다.

진행 중인 quote·chart·indices·종목 업종 조회는 같은 요청끼리 Promise를 공유합니다. 차트는 모든 범위를 한 번에 가져오는 기존 방식이며 quote와 같은 원시 현재가 조회도 공유합니다. 브라우저 취소는 다른 대기자의 작업을 취소하지 않습니다. GET 브리핑은 야간선물·업종의 캐시를 즉시 사용하고 만료된 값은 백그라운드 갱신합니다. cold에서는 공유된 최대 1.5초만 기다린 뒤 unavailable/null을 반환하되 수집은 계속해 다음 요청에 반영합니다. 실패·분류 누락은 60초 음성 캐시를 사용하고 성공 업종은 하루 보관합니다. POST의 전체 45초 예산은 유지합니다. 지수 스냅샷에는 기본 20초 완료 캐시가 있으며 `KIS_INDEX_SNAPSHOT_CACHE_TTL_MS`로 조정합니다.

현재가 완료 캐시는 장중 25초, 지수 20초, 분봉(1일)은 60초입니다. 만료된 성공값도 즉시 `source=cache`로 응답하고 백그라운드에서 갱신하며, 실패 시 기존 값과 원래 `asOf`를 유지합니다(실패 재시도 간격 최소 30초). 장중 값은 15:30 마감 때 한 번 더 갱신하고, 장후·휴장일에 받은 값은 다음 KRX 장 시작까지 유지합니다. 내장 달력의 지원 연도를 벗어나면 무기한 고정하지 않고 짧은 TTL로 되돌아갑니다. `KIS_STOCK_CHART_CACHE_TTL_MS`는 분봉/전체 묶음 갱신 간격, `KIS_INDEX_SNAPSHOT_CACHE_TTL_MS`는 장중 지수 TTL만 조정합니다.

차트의 3개월·1년 일봉과 5년 월봉은 다음 거래일 마감까지 재사용합니다. `server/cache/market-v1/`에 기간별 원본과 전체 묶음을 임시 파일→rename으로 저장해 서버 재시작 직후에도 응답합니다. 해당 경로는 `FE/.gitignore`의 `server/cache/` 규칙으로 제외됩니다. 손상된 JSON/형식은 캐시 미스로 처리하며, 읽기 전용 파일시스템에서는 메모리 캐시로 동작합니다. 새 수집은 마지막 날짜 이후와 최근 14일(5년 월봉은 62일)을 다시 받아 정정값을 덮어씁니다. KIS의 한 번당 100행 제한은 페이지 조회로 이어받습니다. 1년은 최대 390달력일의 실제 일봉이며, 5년 월봉을 일봉으로 취급하지 않습니다. 분봉의 후속 갱신은 최근 한 페이지를 같은 거래일 원본에 합칩니다.

`refresh-ahead`는 Node 운영 서버와 Vite 개발 서버의 `configureServer`에서 시작하고 종료 때 타이머를 정리합니다. 빌드·테스트·정적 preview에서는 주기 타이머를 시작하지 않습니다. 서버 시작 시 최신 모델 TOP5 현재가·전 기간 차트·구성 관측용 일봉과 기존 3개 지수를 예열합니다. 분석의 새 TOP5 현재가는 completed 발행 전 실행 잠금 안에서 최대 6초만 기다립니다. 캐시를 재사용하며 실패·시간 초과도 결과 발행을 막지 않습니다. 발행 직후 추적 목록을 새 TOP5로 교체하고, 1위부터 전 기간 차트·상관/실측용 일봉을 순서대로 준비하며 다음 거래일도 기존 KIS 달력 캐시에 채웁니다. 연속 실행은 진행 중 이력 하나를 마친 뒤 최신 목록으로 이어가고, 과거 목록을 대기열에 쌓지 않습니다. 현재가 준비도 동시 5건으로 제한합니다.

장중 현재가·지수는 30초, 분봉은 60초 주기로 갱신하며 마감 뒤 한 번 갱신 후 다음 장까지 쉽니다. `REFRESH_AHEAD=0`이면 주기 갱신과 발행 후 백그라운드 예열을 끕니다. 발행 전 현재가 준비는 완료 직후 표시를 위한 최대 6초의 사용자 작업이므로 유지합니다. 브리핑 매크로의 기존 SWR 정책은 유지합니다. KIS 공용 제한기는 사용자 요청을 우선하고 백그라운드 호출은 최대 30회/분으로 제한합니다. 기본 공용 한도는 여전히 1 RPS입니다. 최초 TOP5 전체 이력 수집은 수 분 걸릴 수 있고, 상세에는 수집 중 안내를 표시합니다. 이미 진행 중인 동일 예열·화면 조회는 기존 Promise와 캐시 키를 공유합니다. 1분마다 `[refresh-ahead]` 로그에 실제 사용자/백그라운드 호출 수와 `EGW00201` 수를 비밀 없이 기록합니다.

클라이언트 캐시는 30분 유지하며 현재가·지수 `staleTime`은 20초, 분봉 60초, 일봉 탭 10분입니다. 차트 묶음 한 번으로 함께 받은 다른 기간 탭도 채웁니다. 같은 종목의 기존 값은 조용히 갱신하고, 다른 종목으로 이동할 때 이전 종목 값을 보여주지 않습니다. 차트·현재가·지수·대시보드의 요청 제한은 75초이며 narrative POST는 60초입니다.

서버의 읽기 전용 `getDailyHistory(code, { start?, end?, allowNetwork? })`는 캐시의 1년 일봉을 원 단위 raw OHLC·거래량(없으면 null)으로 반환합니다. 네트워크 기본값은 false이며 true도 백그라운드 레인만 사용합니다. 저장소 루트는 기존 `pipelineProjectRoot()`로 계산하고 `outputs/market_index_history/KOSPI.csv`의 KIS 거래일을 우선 참조합니다. 없거나 손상되면 내장 KRX 달력을 사용합니다. 거래일 누락은 `missingDates`로 공개하며, 상장 전·거래정지로 임의 판정하거나 가격을 보간하지 않습니다. 달력 미확인·기간 부족·누락은 `complete:false`입니다. `end` 기본값은 현재 형성 중 일봉을 제외한 마지막 완료일입니다.

공통 스로틀·진행 중 Promise·Gemini 생성 동시성 및 쿨다운은 Node 프로세스/인스턴스별 메모리 상태입니다. 디스크 캐시 파일을 공유해도 인스턴스 사이의 호출 제한이나 재생성 잠금을 보장하지 않습니다. 다중 인스턴스와 Python 작업은 계좌 전체 한도를 공유하므로 운영 시 공용 제한기·분산 잠금 또는 단일 호출 담당자를 별도로 마련해야 합니다.

실전 KIS 야간선물은 현재가→분봉 두 경로에서 명시된 날짜·시각이 야간 범위일 때만 제공합니다. `KIS_NIGHT_FUTURES_MARKET_CODE`(기본 `CM`)와 `KIS_NIGHT_FUTURES_CODE`(기본 만기 규칙 계산)로 덮어쓸 수 있습니다. 공식 예제에 야간 REST 시장코드는 명시되지 않으므로 실제 환경 확인이 필요하며 확인할 수 없는 관측은 unavailable입니다.

지표 ID는 `KOSPI200_NIGHT`이며 `source="kis"`, `unit="pt"`, `session="open"|"closed"|null`을 제공합니다. 야간 범위는 KST 18:00~익일 06:00이며 자정 이후 요청·응답의 24~30시 표기를 정규화합니다. 종료봉 30:00:00까지 허용하고 미래·주간·오래된 관측은 제외합니다.

서버 환경의 `GEMINI_API_KEY`로 Gemini를 활성화하고 `GEMINI_BRIEFING_MODEL`(기본 `gemini-3.8-flash`)로 모델을 지정합니다. 키는 FE 클라이언트 환경 변수에 넣지 않습니다. 매크로 캐시는 `BRIEFING_MACRO_CACHE_TTL_MS`(기본 600000), Gemini 설명 캐시는 실행·TOP5·공개한 수급·주의·기사 상태/id/제목/URL/출처 기준이며 생성 당시 매크로 스냅샷을 `outputs/briefing-narrative.json`에 원자적으로 보관합니다. 새 매크로와 다르면 `macroStale`로 표시하고 성공 후 최소 10분·실패 후 60초 간격을 적용합니다. 자세한 필드와 실패 계약은 [API 계약](docs/api-contract.md)을 따릅니다.

`narrative.macroAsOf`는 설명 생성에 사용한 매크로 기준 시각, `macroStale`은 현재 관측과 스냅샷의 값·시각·문맥이 다른지 나타냅니다. GET은 오래된 설명도 이 표시와 함께 유지합니다. Gemini는 `thinkingLevel="LOW"`, `includeThoughts=false`, 출력 최대 3072토큰, temperature 0.1이며 호출 최대 35초입니다. POST 전체 예산은 준비 조회·업종을 포함해 45초, FE 요청 제한은 60초입니다. 준비 조회는 최대 9초 후 확보한 데이터·캐시·미수집 기본값을 사용합니다.

분석에 필요한 지수 이력은 `MARKET_INDEX_SOURCE=kis`가 기본이고 `pykrx`로 기존 경로를 선택할 수 있습니다. KIS 실전 구성으로 2019-06-03부터 완료 거래일까지 수집해 루트 `outputs/market_index_history/KPI200.csv`, `KOSPI.csv`에 보관합니다. 최초 실측은 지수별 1,813행에 약 123초(재시도 포함 HTTP 109회), 즉시 재실행은 약 2.8초(HTTP 2회)였으며 이후 최근 5거래일과 신규 날짜만 갱신합니다. 캐시 손상 시 전체 수집하므로 첫 실행은 더 오래 걸릴 수 있습니다. 출처·호출 수는 같은 폴더의 `latest-request.json`과 파이프라인 로그로 확인합니다. 기존 Python 단계는 루트 `.env` 우선 동작이 남아 있고 새 지수 수집기만 외부 요청 환경을 우선하므로, 다른 수급 단계의 실전/모의 설정은 별도로 확인해야 합니다.

검증: `npm test`, `npm run typecheck`, `npm run build`. 브라우저 점검 도구는 `scripts/verify/`에 있으며 새 산출물은 루트 `outputs/ui-verification/`에 저장합니다. 과거 화면·점검 기록은 [materials](../materials/README.md)에 모았습니다.
## 시연 전 체크리스트

1. FE에서 `npm run dev -- --host 127.0.0.1 --port 5173 --strictPort --force`로 서버를 시작합니다. 수급은 검증 전까지 기본 비공개로 둡니다. 헤더 실행 버튼을 감추려면 기동 전에 PowerShell에서 `$env:VITE_DEMO_HIDE_RUN='1'`을 설정합니다(기본 off, 서버 POST 기능은 유지). 원래 상태는 `Remove-Item Env:VITE_DEMO_HIDE_RUN` 후 서버 재기동으로 복원합니다.
2. FE에서 `node scripts/demo/warmup.mjs http://127.0.0.1:5173`을 한 번 실행합니다. GET만 순차 호출하고 1.1초 간격으로 대기합니다. 상태·지수·브리핑·전체 순위·TOP5 현재가/전체 차트 범위를 준비하며 HTTP 상태·시간·빠진 지표 수·요약 종류를 표로 확인합니다. 분석·AI 생성·성과 수집 POST는 실행하지 않습니다. 공급자 대기열을 포함해 요청별 최대 120초를 기다리므로 화면 기본 15초 제한과 다릅니다.
3. 시연·전시는 반드시 위 개발 서버로 띄웁니다. 토큰 없이 방문객 실행을 허용하려면 ADMIN_API_TOKEN과 CRON_SECRET을 모두 비워 두고 loopback 주소로 접속합니다. 서버를 켜고 예열한 뒤 화면에서 분석을 한 번 실행해 KIS 토큰을 캐시해 둡니다.
4. 분석의 마지막 ‘AI 요약 생성’(8/8단계)이 끝나면 모델 순위·브리핑·Gemini 요약이 함께 표시되는지 확인합니다. 현재가 준비에 최대 6초가 추가될 수 있으며, 실패·시간 초과에도 완료됩니다. 새 TOP5는 자동 예열되므로 다시 warmup을 실행할 필요는 없습니다. 새 1위 상세 가격 이력과 구성 카드의 상관·실측 자료는 발행 후 순서대로 수집하므로 캐시가 없으면 수 분 기다려 확인합니다(`REFRESH_AHEAD=0`이면 이 자동 예열은 꺼짐). 서버의 `GEMINI_API_KEY`가 필요하며, `BRIEFING_AUTO_NARRATIVE=0`으로 자동 생성을 끌 수 있습니다(기본 켜짐). 자동 생성은 실행당 최대 한 번이며 같은 입력의 유효 캐시를 재사용합니다. 최대 30초 안에 생성하지 못하거나 키 미설정·실패·검증 탈락·쿨다운이면 자동 생성 문장(template)으로 분석을 완료합니다. 필요한 경우 기존 ‘다시 생성’ 버튼을 사용합니다. 수동 재생성은 기존 10분 갱신 정책과 서버 쿨다운을 따릅니다.
5. 홈·순위·종목·기록을 확인하고 시세가 준비된 뒤 시연합니다. 방문객이 실행하면 약 30~40초 동안 마지막 완료 결과를 유지하고 완료 후 새 결과로 교체합니다. 새로고침·새 탭도 같은 서버의 이전 결과를 받으며, 실패해도 유지합니다. 실행 표시줄에서 진행 중·실패와 이전 결과 표시를 확인합니다. 서버를 재시작한 경우 완료 마커가 있을 때만 기존 결과를 다시 읽고, running·failed 마커만 남으면 빈 결과를 표시하므로 재예열합니다.

시장 지표가 unavailable이면 해당 카드만 숨기고, 모두 없으면 안내 한 줄을 표시합니다. API의 상태·출처·시각은 보존하며 화면에서는 헤더의 데이터 출처 접힘 또는 카드 하단으로 모읍니다. 부분 자동 생성 요약은 ‘AI 요약 · 일부 자동 생성 문장 포함’ 배지와 필드별 ‘자동 생성’ 태그로 구분합니다.

## 근거를 확인하는 종목 리포트

`GET /api/stock-insight?code=<6자리>`는 모델 순위와 기간별 비교, 실제 입력의 백분위, 직전 미국장과의 과거 통계, 기사 출처·한계를 제공합니다. 기존 분석 API와 별도로 읽기 전용이며 분석이나 Gemini POST를 호출하지 않습니다. TOP5 구성은 60거래일 공통 일수익률 상관행렬과 검증된 업종 중복·고상관 관측을 추가합니다. 최적화나 매매 권유는 하지 않습니다.

새 분석부터 STEP2 결과에 20일·120일 3시드별 평균 rank-zscore의 순위·점수·일치도와 마지막 실제 입력 백분위가 저장됩니다. 최종 점수와 순위는 기존 연산을 그대로 사용합니다. 기존 결과도 계속 읽으며 새 열이 없으면 추가 근거만 생략합니다. 특징의 백분위는 모델 기여도나 순위의 원인이 아닙니다. 실제 모델에 없는 5일·20일 누적 수익률을 설명용 모델 입력으로 만들지 않습니다.

일봉 자료는 캐시 전담 모듈의 `getDailyHistory(..., {allowNetwork:false})`로만 읽습니다. 첫 TOP5 예열이 끝나기 전에는 ‘데이터 준비 중’이 보일 수 있습니다. 나스닥 1년 통계는 200일 이상, TOP5 상관행렬은 최근 60거래일 중 공통 55일 이상에서 표시하며 결측을 0으로 채우지 않습니다. Yahoo 나스닥 이력은 백그라운드로 읽어 하루 재사용합니다. 같은 미국장이 휴장 차이로 여러 한국장에 연결될 수 있고 과거 통계는 미래 결과나 인과를 뜻하지 않습니다. 상세 산식·표본·선택 필드는 [API 계약](docs/api-contract.md#근거-투명형-리포트-추가-계약)을 따릅니다.

매크로 확보 여부 때문에 바뀌는 주의 문구는 설명 캐시 키에서 제외합니다. 생성 당시 시장 스냅샷과 현재 시장의 차이는 기존 `macroStale`로 알려주고, 실행·종목·기사 사실이 같은 검증된 설명을 계속 사용합니다. 현재 지문과 일치하는 디스크 캐시만 재사용하며 다른 정책의 지문은 이관하지 않습니다. 새 피처·통계는 LLM 입력에 넣지 않습니다.

가격 이력은 원 단위 눈금·기간 시작가 기준선·마지막 관측·최고/최저와 함께 표시합니다. 포인터·터치 및 좌우 키로 같은 관측을 탐색할 수 있고 기존 스텝 버튼·음성 안내도 제공합니다. 전일 종가를 새로 추정하지 않으며 기간 시작 관측가 기준임을 표시합니다.


시연 시 ‘지난 관측 · 기준 시각’은 중립적인 과거 데이터 표시입니다. 장중 30분 초과 또는 직전 완료 거래일 마감보다 이전의 수집 시각에 표시하며, 오래된 실제 체결 시각을 수집 시각으로 추정하지 않습니다. 시장 캐시는 14일 보관 상한을 적용합니다. 예열 실패는 1분부터 최대 10분 간격으로 재시도하며 warmup 마지막 두 GET이 차트 준비 이후의 브리핑·TOP1 근거를 확인합니다.

일부 자동 생성 문장이 포함된 AI 요약은 그 사실과 사용 모델을 함께 표시합니다. 템플릿의 조사·대상 세션 문구를 개선해도 기존 입력 원문과 해시는 유지하므로 유효한 저장 설명을 다시 유료 생성할 필요가 없습니다. 상세 정책은 API 계약의 ‘캐시 보관과 설명 검증 보완’을 따릅니다.
